# /review — Проверка перед коммитом

**Когда использовать:** перед коммитом или PR. По умолчанию проверяет staged изменения (`git diff --staged`).

## Workflow

1. **Reviewer** — проверяет staged-изменения или указанные файлы
2. При критичных issues → **Debugger** (только с подтверждения)
3. **Test-Runner** — верификация после фиксов

## Как выполнять

1. Получи `git diff --staged` или указанные пользователем файлы
2. Reviewer проверяет качество, архитектуру, безопасность
3. При критичных проблемах — предложи фикс, спроси подтверждение
4. После фиксов — Test-Runner

## Связь с агентами

- @reviewer — code review
- @debugger — исправления (по подтверждению)
- @test-runner — верификация
